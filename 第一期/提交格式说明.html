1. 仓库怎么建（命名规范）

项目 要求
仓库名 LightChaser-Training-编号
示例 LightChaser-Training-01
编号怎么找 《2026追光培训进度登记表》里你名字前面的「序号」（1~72）
编号格式 两位数，不足两位前面补 0（写 01，不要写 1）
可见性 Public（公开）——私有仓库学长打不开，等于没交
初始化 创建时勾选 Add a README file
数量 前三章只用这一个仓库，不要每章建一个

⚠️ 如果你按旧版教程建了 my-c-practice（或用了自己的名字、姓名拼音）：进仓库 Settings → Repository name 改名成 LightChaser-Training-你的编号 即可。GitHub 会自动把旧链接跳转到新地址，之前的提交记录一条都不会丢。

为什么用编号，不用姓名拼音：本期 72 位同学同时交作业，编号和在线登记表一一对应，学长拿登记表一对就知道是谁的仓库——不用猜拼音怎么写，也不会因为重名或拼写不一致而认错人。

💡 仓库名只有编号、看不出姓名，这是刻意为之：仓库是公开的，不暴露个人信息。 学长靠登记表里的编号对应到你，所以你不需要在 README、代码或截图里写姓名、班级、学号。

3. 第 1 章：交 C 源码文件

练习 必须的文件名 要求
Hello World hello.c 编译运行成功，输出 Hello, LightChaser!
简易计算器 calculator.c 支持 + - * /，除数为 0 要提示
1~100 奇数和 odd_sum.c 打印 1~100 的奇数和
指针交换 swap_pointer.c 必须自己写，用指针交换两个变量的值
malloc 求平均 average_malloc.c 动态申请数组求平均值，记得 free
成绩单（选做） score_struct.c 结构体存姓名 + 分数

通用要求

  • 一个练习一个文件，文件名用小写 + 下划线（swap_pointer.c，不要 Swap Pointer.c）。
  • 每个 .c 文件必须能独立编译运行，提交前自己先 gcc 跑一遍。
  • 源码里写点注释，说明这段在干什么——学长看的是你有没有真的懂。
  • 用 C++ 也可以，但文件后缀要和内容一致（用 .cpp 就写 .cpp）。

4. 第 2 章：交截图

第 2 章交截图，不用交代码。对应教程本章的三条验收，截这三张：

截图 截什么 建议文件名
① 网页版 AI 在网页版 DeepSeek 里，把第 1 章的指针代码贴进去、AI 给出解释的界面 2-1_网页版AI解释指针.png
② 编辑器里用 AI 在 Trae / VS Code 里选中一段代码，AI 面板给出解释或找出 bug 的界面 2-2_编辑器里用AI.png
③ API 跑通 终端里运行 python llm_test.py，成功打印出模型回答的界面 2-3_API跑通.png

截图要求

  • 要能看出是你自己的操作：画面里最好带上你的代码内容、文件名或终端命令，别只截一句"成功了"。
  • ⚠️ 只截必要区域，别把无关窗口截进去：截图前先关掉微信 / QQ、邮箱、其他浏览器标签和文件管理器——桌面文件名、聊天内容、通知弹窗都会跟着一起进公开仓库。用 Win + Shift + S 框选需要的部分，不要整屏截。
  • 格式用 .png / .jpg，单张别超过 2 MB（仓库不是图床，塞大图会让仓库很臃肿）。
  • ⚠️ 截图前检查画面里有没有 API Key（.env、代码、终端回显里都可能露出来）。有就打码或换成占位符，别为了交作业把 Key 送出去。
  • 如果 llm_test.py 你也写了，顺手放进 02_大模型基础/ 更好，但不放也算完成——截图能证明跑通就行。

5. 第 3 章：交仓库链接，不用额外写说明

第 3 章不要求写任何说明文档，仓库本身就是交付物。只要满足：

  • ☐ 仓库存在，且是 Public
  • ☐ 仓库里有多条提交记录（教程要求至少 2 条），能看出你走通了 clone → 改 → push
  • ☐ 把仓库链接填进《2026追光培训进度登记表》的「GitHub 链接」列

想更稳妥的话，可以随便改一行代码再提交一次，git log --oneline 里能看到至少 2 条，就稳了。

提交信息写清楚做了什么：每完成一个练习就提交一次，信息用「做了什么」直说，比如 完成 Hello World、修正计算器除零判断；别写 111、asdfgh、update 这种。git log --oneline 一眼能看懂，学长验收快，你的提交历史本身也是成长记录。

6. .gitignore 模板（放了第 2 章代码才需要）

只交截图、没往仓库里放代码的话，这一节可以跳过。 但只要你把 llm_test.py（或任何带 Key 的代码）放进了仓库，就必须建 .gitignore 并写入 .env——这是唯一挡住 Key 泄露的东西。

7. 🚨 三条红线（违反要重做）

① 绝不提交 API Key / .env 文件

.env 里是你的 DeepSeek Key。一旦推上 GitHub，几秒内就会被爬虫扫走盗刷。 只要仓库里放了第 2 章的代码，就必须建 .gitignore 并写入 .env（模板见第 6 节）。 另外截图时也别把 Key 截进去（见第 4 节）。

② 不提交编译产物

.exe、.o、.out 是 gcc 生成的，不是你的源码，别人也用不上，写进 .gitignore。

③ 不提交别人的代码和无关大文件

抄来的代码要注明来源；视频、安装包、几百 MB 的数据集不要往仓库里塞。

⚠️ 万一 Key 不小心提交上去了：立刻去 platform.deepseek.com 删掉那个 Key 并新建一个（删掉是唯一有效的止损），再把代码里的 Key 换成新的。 顺序不能反——旧 Key 已经泄露，只改代码救不回来。

8. ✅ 提交前自检（逐条打勾）

  • ☐ 仓库名是 LightChaser-Training-编号（两位数，如 01），且是 Public
  • ☐ 01_C语言基础/ 里 5 个必做文件都在（hello / calculator / odd_sum / swap_pointer / average_malloc）
  • ☐ 每个 .c 文件我都亲手 gcc 编译并运行过，没有报错
  • ☐ 02_大模型基础/ 里 3 张截图都在，能看清是我自己的操作
  • ☐ 截图里没有露出 API Key
  • ☐ 截图里没有微信 / QQ 聊天、邮箱、无关文件名等私人内容
  • ☐ README、代码注释里没有姓名、班级、学号、手机号等个人信息
  • ☐ 在仓库搜索框搜 sk-，搜不到我的 Key
  • ☐ 放了代码的话，.gitignore 里有 .env，且 .env 本身没有被提交
  • ☐ git log --oneline 至少有 2 条提交记录，信息看得懂
  • ☐ 仓库链接已填进《2026追光培训进度登记表》的「GitHub 链接」列

9. 📮 怎么算"交了"（交付流程）

  1. 打开你的仓库，复制地址栏链接： https://github.com/你的用户名/LightChaser-Training-01
  2. 打开《2026追光培训进度登记表》，找到自己那一行，把链接填进 「GitHub 链接」 列
  3. 你已完成的章节，在该章单元格下拉选 √（未完成留空）
  4. 把链接发到培训群，或直接发给对接的学长
  5. 学长按这份格式逐项核对；格式不对会被打回补交，早交早改

🕐 第 1~3 章需在 10.26 前完成并交付，作为最终面试的验收依据。

10. ❓ 常见问题

Q1：我用的 C++ 行不行？ 行。第 1 章重点是语法和指针，C 或 C++ 都可以，但文件后缀要和内容一致（用 .cpp 就写 .cpp）。

Q2：练习没全做完能先交吗？ 可以，但没做完的章节别打 √。学长看的是你实际做到哪一步，诚实填写不影响评价，虚报才会扣分。

Q3：push 时让我输密码，输了不对？ GitHub 现在不认账号密码。要么用 Personal Access Token 当密码，要么配 SSH。见 Git 入门。

Q4：我按旧版教程建了 my-c-practice（或用了自己的名字），一定要改名吗？ 建议改，一分钟的事（Settings → Repository name），改成 LightChaser-Training-你的编号。不改的话，请在登记表「备注」里写明你实际的仓库名，否则学长可能找不到。

Q5：仓库一定要 Public 吗？ 是。私有仓库学长打不开，无法验收。确实不想公开，可以在 Settings → Collaborators 里把学长加为协作者，并在备注里说明。

Q6：第 2 章的截图可以用手机拍屏幕吗？ 可以，但要能看清内容。推荐用电脑截图工具（Windows：Win + Shift + S）。

Q7：.env 被我提交了怎么办？ 见第 7 节红线①：先去 DeepSeek 后台删掉那个 Key，再改代码。顺序不能反。

Q8：我可以多建几个仓库吗？ 前三章成果请集中在一个仓库里，方便验收。之后的进阶章节可以另建仓库，也可以继续放进同一个仓库的不同文件夹。

Q9：我不知道自己的编号是多少？ 打开《2026追光培训进度登记表》，找到自己那一行，最左边「序号」列就是你的编号（1~72），写成两位数（01、07、72）。
