## 2. STM32 各章交什么

第 1~5 章每章一个文件夹，**只交关键屏幕截图**（代码关键段、编译/烧录结果、串口或运行现象），**不交工程源码**；不需要写 README、芯片型号、工具链、编译烧录步骤。有实物运行可另附照片或录像（选交）。

**第 6 章最终考核只交作品说明、接线图与演示视频链接，不交工程源码。**

| 章 | 文件夹 | 必交内容 |
|---|--------|----------|
| 1 | `01_env_blink/` | 代码截图 + 编译/烧录成功截图 |
| 2 | `02_gpio_key/` | 代码关键段 + LED/按键运行截图 |
| 3 | `03_uart_debug/` | 串口代码 + 收发截图 |
| 4 | `04_exti_timer/` | 中断/定时器代码 + 运行截图 |
| 5 | `05_pwm_adc/` | PWM/ADC 代码 + 运行或串口截图 |
| 6 | `06_final_project/` | **作品说明** + **演示视频链接** + 接线图（不交工程源码） |

**通用要求**

- 每章一个文件夹，只放该章关键截图；**不交源码/工程文件**，截图要能看出关键代码与运行结果。
- 截图只截必要区域，别把微信 / QQ / 邮箱等私人内容截进去。
- **第 6 章最终考核不交工程源码**，只交作品说明、接线图与演示视频链接。

## 4. 演示视频怎么上传 GitHub

**不要直接把视频 `git add` 进仓库**：GitHub 单文件超过 100 MB 会被拒绝，仓库也会变得很臃肿。

**推荐方式：GitHub Release 附件**

1. 打开你的仓库 → 右侧 **Releases** → **Draft a new release**。
2. 填一个 tag（如 `v1.0-final`）和标题（如 `第二期最终考核作品演示`）。
3. 在附件区上传 `演示视频.mp4`（建议 1~3 分钟、1080p、**100 MB 以内**）。
4. 点 **Publish release**，复制视频附件的下载链接。
5. 把链接写进 `06_final_project/作品说明.md` 的「演示说明」一节，并在 `演示视频链接.txt` 里放一份。

**视频内容建议**

- 开头一句话：作品名称 + 你的编号（不要露脸、不要报姓名）。
- 上电 → 功能演示 → 关键操作 → 最终结果。
- 画面能看清接线与运行现象；不要只拍屏幕不拍实物。

> 如果视频确实超过 100 MB：先压缩（剪短、降分辨率），或上传到 B 站 / 网盘后在 `作品说明.md` 放链接，并把**访问密码（如有）**写清。**最终以 GitHub 上可访问为准**。

## 5. 机械作业交什么

> 3D 设计统一交 **STEP 通用格式**（`.step` / `.stp`，也接受 IGES `.igs` / `.iges`），SolidWorks 可直接打开；原生源文件（`.f3d` / `.sldprt` / `.3dm`）可选，建议一并提供。

### 第 26 课 · 萝卜塔

- **STEP**：`萝卜塔.step`（或 `.stp`），单位 mm
- `过程截图/`：3~5 张，覆盖草图、关键特征、完成状态
- `说明.md`：用的软件、用了哪些命令、关键尺寸怎么定、与教程的偏差及原因

### 第 42 课 · 汤勺

- **STEP**：`汤勺.step`（或 `.stp`）
- `完成图.png`：渲染图或截图（能看清曲面过渡）
- `说明.md`：建模步骤、曲面/放样命令、修改点
- 选做：需要打印时在 Q 群提出，后期按需求提供部分 3D 打印服务；打印后附照片与参数

**通用要求**

- 必交 **STEP**，不只交截图；文件命名用中文作业名，别用 `Untitled`。
- 原生源文件可选；若提供，和 STEP 放在同一作业目录。
- 导出的大 STL 不直接进仓库；需要时放 Release 或网盘，在对应 `说明.md` 里写链接。
- 按教程跟做允许微调，但要在 `说明.md` 写清「改了什么、为什么」。用非 Fusion 软件时注明用的软件。

## 6. 🚨 红线（违反要重做）

1. **不提交 API Key / `.env`**：仓库里搜 `sk-` 搜不到才算过关。
2. **不提交编译产物**：`Objects/`、`Listings/`、`*.hex`、`*.axf`、`*.o` 都不交。
3. **不提交他人成果**：允许参考、复刻开源方案，但代码、接线、结构、调试必须个人自制，并在作品说明中注明参考来源；不能直接提交他人完整工程或找人代做。
4. **不提交个人信息**：姓名、班级、学号、手机号、宿舍、身份证号都不写进仓库和视频。
5. **不提交无关大文件**：视频走 Release / 网盘，仓库只留代码、说明、截图。

## 9. ❓ 常见问题

**Q1：我可以新建一个二期仓库吗？**
不建议。沿用一期仓库，验收时按编号找一次就够；一期没建仓库的，按 `LightChaser-Training-编号` 新建。

**Q2：视频超过 100 MB 怎么办？**
先压缩（剪短、降到 1080p 以下）；仍超限就上传 B 站/网盘，在 `作品说明.md` 放链接和访问密码。GitHub Release 单文件上限更大，但也别传超大文件。

**Q3：机械作业一定要用 Fusion 360 吗？交什么格式？**
软件不强制：教程以 Fusion 360 讲解，但可以用 SolidWorks / Rhino（犀牛）等完成。**统一交 STEP 通用格式**（`.step` / `.stp`，也接受 IGES），SolidWorks 可直接打开；原生源文件可选。打印不强制；需要时在 Q 群提出，后期按需求提供部分 3D 打印服务。

**Q4：STM32 最终作品可以自拟题目吗？**
可以，选题自由发挥；但**硬件范围固定**——主控必须是 **STM32F103C8T6**，其余模块自行购买（团队不提供借用）。做传感器、显示、控制、小游戏都可以。

**Q5：可以参考或复刻开源方案吗？**
可以。允许参考各种开源方案、允许复刻，但**代码、接线、结构、调试必须个人自制**，并在 `作品说明.md` 的「参考来源」写清参考了什么、自己改了什么。直接提交他人完整工程、或找人代做，按抄袭处理。

**Q6：机械 STEP 文件很大怎么办？**
STEP 通常比原生文件大；超过 100 MB 就放 Release 或网盘，仓库里放截图 + 链接 + 说明。

**Q7：硬件范围是什么？**
主控固定为 **STM32F103C8T6** 最小系统板；传感器、显示、执行器等模块自行购买，团队不提供借用。

**Q8：最终考核要交工程源码吗？**
不需要。最终考核只交 **完整作品说明 + 演示视频链接**，不交工程源码。
